# Native MySQL QueryManager

This is the C++ backend for the original JoinServer/DataServer `CQueryManager` API. It uses the actual libmysqlclient C API; it does not use unixODBC, invent database rows, install schema or implement stored-procedure bodies. Native source wrappers should include `query_manager.hpp` under `MU_NATIVE_MACOS` and omit the original ODBC `QueryManager.cpp`. The shared library target exports `gQueryManager`; each server executable links its own instance.

`Configure(MuMySqlConfig)` sets the explicit host, port, database, user/password, charset, timeouts and TLS mode. Configuration is authoritative, including an empty password. Alternatively, the original `Connect(odbc,user,pass)` loads `MU_MYSQL_HOST`, `MU_MYSQL_PORT`, `MU_MYSQL_DATABASE`, `MU_MYSQL_USER`, `MU_MYSQL_PASSWORD`, `MU_MYSQL_SSL_MODE`, `MU_MYSQL_SSL_CA`; explicit endpoint/database are required and the legacy ODBC argument is ignored. Environment credentials override legacy user/pass arguments when present. Default charset is Latin-1; default TLS mode is required, with optional preferred/disabled/verify_ca/verify_identity modes.

The current SSH tunnel workflow keeps `required`: this mode requires an encrypted MySQL connection. `verify_ca` additionally verifies the CA chain, and `verify_identity` also verifies the server hostname. An empty `SslCa` by itself is valid with `required`; SSH forwarding does not enable MySQL TLS on the VPS. [MySQL TLS mode semantics](https://dev.mysql.com/doc/refman/8.4/en/using-encrypted-connections.html).

No credentials or formatted SQL/blob values are printed by this backend. `LastError()` contains a sanitized status or MySQL numeric error code. `Diagnostic(query)` preserves the old method signature and does not expose its supplied query. `GetStatus()` reports the held connection state, not a database-wide health check. `GetRowCount()` reports first selected rowset row count or the DML affected count; existing ODBC return codes are success 0 and no-data 100.

`BindParameterAsString/Binary` use one-based positions and copy caller memory. String bindings stop at NUL within the supplied bound; binary bindings preserve every byte, including zeros and custom MU MD5's 16-byte digest. Prepared statements validate the exact placeholder count. Bindings are consumed by a query or cleared by `Close`; missing, extra or invalid parameters fail rather than reuse another query's memory.

Execution materializes the first actual selected rowset and drains additional CALL rowsets/status before returning. Column-name lookup is case-insensitive. Typed getters retain the source atoi/float/int64 conventions, missing-column -1, zeroed missing/NULL strings/blobs and bounded prefixes. Binary columns use raw MySQL bytes, avoiding the original ODBC hex-text detour; the public hex helper methods remain available. Limits are source MAX_COLUMNS=100, result columns <=8192 bytes, formatted queries <4096 bytes, plus configurable total rows/result bytes. Oversized/truncated results fail explicitly.

The whole `Bind→Exec→Fetch/Get→Close` sequence is serialized by thread ownership, not just individual calls. Always call `Close`, including when stopping a cursor early. Callers must drain/shut down their workers before destroying the manager. A failed query releases ownership; dropped connections may reconnect for a later query, but the failed operation is never retried, because a write may already have committed remotely. No query lifecycle here asserts an application transaction across multiple source `ExecQuery` calls.

`query_catalog.json` / `known_queries.hpp` index 348 literal call sites, 271 unique formats and 57 procedure names from original Join/Data `.cpp` files, including inactive version branches. `sql_dialect.cpp` permits only those formats. It converts explicit or bare source `WZ_*` calls to finite known-arity `CALL`, handles `%I64d` formatting, quoted identifiers, source `getdate()`, the exact warehouse `0xFF` byte-fill expression, and the known TOP/window queries. It tokenizes strings and identifiers separately so SQL-looking text inside a value remains data. It rejects statement boundaries/comments and unsupported formats, including arbitrary GameServer Lua `ExecQuery("%s",...)`; that script boundary still needs an explicit native SQL policy.

The session uses `NO_BACKSLASH_ESCAPES` so SQL Server quote/backslash rules are retained for existing formatted literals. This is a finite dialect adapter, not a general SQL Server transpiler. Existing printf-interpolated values remain a legacy source boundary; changing all those call sites to value bindings is separate work. The VPS must already supply the exact migrated tables/procedures, including first selected result rows and binary/default/expiry/transaction semantics. A Windows `.bak` is not made MySQL-compatible by this backend.

On this host `pkg-config mysqlclient` locates Homebrew MySQL 9.3.0 headers/library. `mu_mysql` links `PkgConfig::MYSQLCLIENT` and `mu_platform`. Without the dependency the build provides explicit failure, never a fake connected database. Tests exercise all 271 source formats, known procedure signatures, quote isolation, unsupported input, result/null/prefix/int64 behavior and binary helpers. They compile/link the real C API but do not connect or open sockets; real MySQL prepare/CALL/rollback/reconnect and MU client validation remain required.
